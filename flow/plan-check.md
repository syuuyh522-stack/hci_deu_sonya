## 4. 팀 결정

| 항목 | 결정 | 이유 |
|---|---|---|
| 1. 핵심 플로우 1에서 레이어링 타임라인이 약함 | 1.2 일정 줄마다 입기 / 벗기 / 다시 입기 표시를 붙임 (와이어프레임 반영) | 화면을 거의 그대로 두면서 핵심 기능 1을 핵심 플로우에 넣기 위해 |
| 2. 내 체감 보정이 약함 | 저녁 이후 1.0을 열면 맨 위에 "오늘 어땠어요?" 피드백 카드를 띄우고, 누르면 1.1로 감 (플로우 2에 3~4단계 추가) | 알림을 늘리지 않기 위해. 1.0 와이어프레임의 저녁 모습은 `/design` 에서 반영 |
| 3. 미세먼지가 약함 | 나쁨 이상인 날만 알림 둘째 줄과 1.0·1.2 챙길 것에 "마스크"를 넣음 | 기획서대로 필요한 날에만 알리기 위해. 1.0의 "마스크 필요 없음" 칩은 `/design` 에서 뺄 것 |
| 4. 예보 변경 아침 알림이 기획서 "하루 한 번"과 다름 | 기획서 기능 6에 예외로 넣고, 2.4 알림 시간에서 "예보가 바뀌면 아침에 다시 알려주기"를 켜고 끌 수 있게 함 | 하루 한 번을 원하는 사람과 아침 예보 변경이 필요한 사람(이하은, 참가자 D)을 함께 만족시키기 위해. 2.4 와이어프레임은 `/design` 에서 반영 |
| 5. 플로우에서 생긴 화면(1.2 내일 미리보기와 오늘/내일 전환, 1.3·1.4 하루만 일정 바꾸기, 설정은 온보딩 다시 열기)이 기획서에 없음 | 기획서 "화면 구성"과 기능 2에 새로 넣음 | 기획서와 화면을 맞추기 위해 |
| 6. "이렇게 입을게요" 버튼이 무엇을 하는지 없음 | 누르면 그 옷을 확정해 기록하고 "내일 옷을 정했어요" 안내 후 끝. 다음 날 아침 1.0에 "어제 정한 옷"으로 보여줌 | 핵심 목표 "전날 밤에 정해 두기"가 눈에 보이게 하기 위해 |
| 7. 이하은의 실내외 온도 차이, 무거운 가방 불편이 남음 | 다음 주 사용성 평가 질문에 넣어 실제로 얼마나 불편한지 확인한 뒤 정함. 이번엔 화면에 반영하지 않음 | 근거를 모은 뒤 정하기 위해 |
